# Roster and injury reports

Upload these files at the repository root, preserving public/ and test/ folders. Commit to main, wait for Railway, then hard refresh.

Selecting a game loads both teams' provider roster and current injury reports using the existing API_SPORTS_KEY. Expand each roster to see names, positions and provider groups. Player projections display matched injury reports and warn when a player is absent from the provider roster. Matching uses player and team IDs.

Fetch timestamps are distinct from injury report dates. Reports older than seven days are labeled for rechecking. Empty reports never imply healthy players. Failed reports and unsupported coverage show unknown. Current injury reports are not fetched for historical seasons. For previous games within the current season these remain explicitly current reports, not historical availability.

This release does not verify trades, starting roles, or game-day inactive lists. For upcoming games within seven days, fresh provider out/inactive/IR reports or a fresh injured-reserve roster entry withhold player projections and line comparisons. Missing, stale, future-dated and conflicting reports remain unknown. Questionable/doubtful reports do not imply a playing probability. The latest dated injury report takes precedence over older reports. Current reports never gate past matchups.

Player cards offer an explicit 0–100% workload scenario. It linearly scales the displayed projection and line comparison, not historical averages or playing probability. Scenarios reset when the matchup changes. Unavailable players are withheld rather than shown as a zero-stat under. Workload scenarios do not redistribute touches or alter team scores. Team-score injury scenarios now offer separate 0–14 point offense and defense loss estimates for each team. Offense loss reduces that team’s score; defense loss increases its opponent’s score. These explicit user estimates are applied after schedule strength and manual adjustments, before home field and wind; results show before/after scores. Inputs reset when the matchup changes and editing them invalidates old simulations. Zero does not confirm health. Automatic player valuation remains unfinished; the feed does not establish starting roles or replacement quality. A deduplicated availability review separates reported unavailable, conditional and unresolved entries using existing freshness and matchup gates. Experimental wind behavior is documented in WEATHER-MODEL.md. Home-field behavior is documented in HOME-FIELD.md. Schedule-strength correction is documented in SCHEDULE-STRENGTH.md. Team-season roster membership is provider information, not a confirmed transaction history. Rosters cache one hour; injuries cache 15 minutes; concurrent visitors share requests. Refresh respects those cache windows.

## Automatic NFL maintenance

With API_SPORTS_KEY configured, the server starts an availability sweep on startup and every six hours. It checks unique NFL games in the next seven days, reusing the same cached, guarded roster, official injury, depth and ownership sources as matchup loading. January uses the preceding NFL season. Concurrent sweeps share one job; failed or paginated schedules never count as successful checks.

The Automatic NFL roster checks panel reads /api/roster-maintenance and reports the last completed sweep, games checked, missing reports, unmatched official/depth identities, ownership conflicts and expired/unverified reviewed transactions. This refreshes provider data, not the manually reviewed identity/transaction files. It does not discover and approve every trade or invent replacement workload. Existing matchup refresh intervals still apply.

Status is in memory and resets on process restart. Sweeps require a running server and use the existing API-Sports quota and source caches. Sleeping hosting instances do not run timers; startup performs a fresh sweep. No provider key means no background sweep. This is NFL-only. Final game-day lists remain source- and timing-dependent.
